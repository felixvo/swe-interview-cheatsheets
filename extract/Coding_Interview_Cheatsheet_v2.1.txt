1. Universal Interview Framework
Use roughly this sequence for every coding question:
Restate the problem in your own words
Clarify constraints (n? value range? sorted? duplicates? negatives?)
Walk one example by hand; propose edge cases
State the brute force + its complexity (out loud, don't code it)
Optimize: name the bottleneck, match a pattern
Agree on the approach with the interviewer before coding
Code cleanly, narrating as you go
T est: trace the given example, then your edge cases
State final time/space complexity
Discuss follow-ups and trade-offs
Constraints are hints. n ≤ 10⁵ is the interviewer telling you the target is roughly O(n log n) — see §2.

2. Complexity and Constraints
2.1 Constraint → Target Complexity
⚑ Budget: roughly 10⁶–10⁷ simple operations per second in Python (10⁷–10⁸ in C++/Java). Every
row below is derived from that number, so state which language you're in when you quote it.
Input size n Target complexity Typical approach
n ≤ 10 ⚑ O(n!) permutations, brute force
n ≤ 22 ⚑ O(2ⁿ) subsets, backtracking, bitmask
n ≤ 200 ⚑ O(n³) triple loop, Floyd–Warshall
n ≤ 3,000 O(n²) double loop, 2D DP
n ≤ 10⁵ ⚑ O(n log n) sort, heap, binary search, divide & conquer
n ≤ 10⁶ O(n) one pass, two pointers, hashmap
n ≥ 10⁹ ⚑ O(log n) / O(1) binary search on answer, math, bit tricks
⚑ Why the old table was off: 12! ≈ 4.8×10⁸ — too slow, and even 11! ≈ 4×10⁷ overshoots the Python
budget above (≈3 s measured); 10! ≈ 3.6×10⁶ fits. An array of 10⁸ ints doesn't fit in memory, so "n ≤
10⁸ → O(n)" describes a problem that can't be given as an array — very large n means the input is 
implicit (a range to search over), not stored. T wo caveats worth saying out loud: the small-n rows
assume ordinary pruning (real backtracking rarely visits the full space), and n ≤ 200 → n³ ≈ 8×10⁶ sits
right at the Python ceiling — comfortable in C++, tight in Python.

5.2 Sliding Window
When: contiguous subarray/substring, "longest/shortest window such that…".
Variable-size shrinkable template — O(n), each index enters and leaves once:
left= best= 0
forrightin range(len(a)):
# add a[right] to the window state
whilewindow_invalid():
# remove a[left] from state
left+=1
best= max(best, right- left+ 1)
Longest substring without repeating characters:

left= best= 0
forright, c in enumerate(s):

left= last[c] + 1
last[c] = right

Correctness condition: the window only works when growing/shrinking moves the constraint 
monotonically (e.g. sums of all-positive numbers). With negatives, "subarray sum = k" is not a
window problem — use prefix sum + hashmap (§5.3).
Classics: Minimum Window Substring, Max Sum Subarray of Size K, Fruit Into Baskets, Longest
Repeating Character Replacement.

5.3 Prefix Sum + HashMap
When: subarray sums/counts with negatives allowed; many range-sum queries.
Count subarrays summing to k — O(n):
count= prefix= 0
seen= {0: 1} # empty prefix
forx in nums:
prefix+=x
count+=seen.get(prefix- k, 0)
seen[prefix] = seen.get(prefix, 0) + 1
Classics: Subarray Sum Equals K, Contiguous Array (map 0→−1), Range Sum Query (precompute prefix
array). Pitfall: forgetting to seed {0: 1} — it counts subarrays starting at index 0.
5.4 Binary Search
When: sorted data, rotated sorted arrays, or any monotonic feasibility question ("smallest x that
works").
One template, memorized cold — lower bound (first index with a[i] >= target):
lo, hi= 0, len(a)
whilelo< hi:
mid= (lo+ hi) //2
if a[mid] < target:
lo= mid+ 1
else:
hi= mid
returnlo # == len(a) if all elements < target
Binary search on the answer space — smallest feasible value:
lo, hi= min_answer, max_answer
whilelo< hi:
mid= (lo+ hi) //2
if feasible(mid):
hi= mid
else:
lo= mid+ 1
returnlo
For the largest feasible value: mid = (lo + hi + 1) // 2; lo = mid when feasible, else hi = mid - 1.

⚑ Rotated arrays with duplicates: the "which half is sorted" test breaks when a[lo] == a[mid] ==
a[hi] (e.g. [1,1,1,0,1]). Shrink with lo += 1 and note that worst case degrades to O(n) — say this
out loud, it's the point of the follow-up.
Classics: Search in Rotated Sorted Array, Koko Eating Bananas, Capacity to Ship Packages, Split Array
Largest Sum, First Bad Version. Pitfall: off-by-one. Pick ONE template and never improvise; feasible()
must be monotonic or the search is invalid.
5.5 Fast & Slow Pointers
When: linked-list cycle, middle node, k-th from end, "sequence eventually repeats" (Happy Number).
slow= fast= head
whilefastandfast.next:
slow, fast= slow.next, fast.next.next
if slowis fast: # ⚑ check INSIDE the loop
returnTrue
returnFalse
⚑ The comparison must live inside the loop — this is a real fix, not a formatting choice, and v2 made it
without a flag. Written after the loop (which is how v1's mangled indentation reads), an empty or single-
node list returns True because slow is fast holds trivially, and a list with an actual cycle never exits
the loop at all.
Cycle start: after they meet, reset one pointer to head; advance both one step at a time; the meeting
point is the cycle entrance. Middle node: when fast hits the end, slow is the middle. Pitfall: compare
nodes with is, not ==; guard fast and fast.next in that order.
5.6 Linked-List Reversal
prev= None

cur.next, prev, cur= prev, cur, cur.next
returnprev # new head
Classics: Reverse Linked List, Reverse Nodes in k-Group, Palindrome Linked List (middle + reverse
second half + compare), Reorder List. Pitfall: when the head can change, start from a dummy node
and return dummy.next; draw the pointer diagram before coding.

5.8 Heap / Top-K
When: top k, k-th largest, k closest, merge k sorted lists, running median. heapq is a min-heap; push
negatives for a max-heap.
K-th largest — keep a min-heap of size k, O(n log k):
importheapq
h = []
forx in nums:
heapq.heappush(h, x)
if len(h) > k:
heapq.heappop(h)
returnh[0]
Merge k sorted lists: heap of (value, list_index, node) — the index breaks ties so Python never
tries to compare nodes. Running median: max-heap for the lower half + min-heap for the upper half,
rebalance so sizes differ ≤ 1 — median is a top (or the mean of both tops).
Classics: T op K Frequent Elements, K Closest Points, Meeting Rooms II (min-heap of end times), Find
Median from Data Stream. Pitfall: for top-k, the heap size is k, not n — that's where the log k comes
from. Mention quickselect as the O(n) average alternative.

5.11 DFS on Trees
When: path properties, subtree aggregation, validate BST, LCA.
The shape is always "return info up, update the answer globally." ⚑ v1 gave one template for two
different problems; they need different code.
Diameter (counts edges, so +1 per node):
defdfs(node):
if notnode:
return0
left, right= dfs(node.left),dfs(node.right)
self.best= max(self.best, left+ right) # both sides
returnmax(left, right) + 1 # parent extends ONE side
Max Path Sum (⚑ must clamp negatives — v1 returned 1 instead of 2 on [2,-1]):
defdfs(node):
if notnode:
return0
left= max(dfs(node.left),0) # drop negative branches
right= max(dfs(node.right),0)
self.best= max(self.best, left+ right+ node.val)
returnmax(left, right) + node.val
⚑ Initialize self.best = 0 for Diameter (single node or empty tree ⇒ 0) and self.best = float('-inf')
for Max Path Sum — an all-negative tree has a negative answer.
Validate BST: pass (lo, hi) bounds down; comparing a node only with its parent is wrong. Inorder
on a BST is sorted — k-th smallest. Pitfall: Python recursion limit is ~1000 — for deep/skewed inputs,
sys.setrecursionlimit(...) or go iterative with an explicit stack.

5.13 Graphs: Topo Sort, Union-Find, Dijkstra
Build adjacency first: adj = defaultdict(list).
Topological sort (Kahn's) — dependencies, course schedule; detects cycles:
indeg= [0] * n

Union-Find — connectivity, components, "merge accounts". ⚑ v1 claimed rank/size but only
implemented path compression; without union by size the tree can degrade:

5.14 Dynamic Programming
When: "count the ways", "minimum/maximum cost", "can you reach/partition" — choices +
overlapping subproblems.
The 5-step framework (say it out loud):
State — what does dp[i] MEAN, in one sentence
Transition — dp[i] from smaller states
Base cases
Order — iterate so dependencies are ready
Answer — which cell holds it
Top-down is transcription of the recurrence:
fromfunctoolsimportlru_cache
@lru_cache(None)
defdp(i):
if i < 0:
return0
returnmax(dp(i - 1),dp(i - 2) + nums[i]) # House Robber
1D with O(1) space — keep two rolling variables. 2D (LCS) — ⚑ the padding convention is part of the
template: dp is (n+1)×(m+1) zeros and dp[i][j] means LCS of a[:i], b[:j]:
dp= [[0] * (m + 1) for_ in range(n + 1)]
fori in range(1, n + 1):
forj in range(1, m + 1):
if a[i - 1] ==b[j - 1]: # ⚑ shift into the strings
dp[i][j] = dp[i - 1][j - 1] + 1
else:
dp[i][j] = max(dp[i - 1][j],dp[i][j - 1])
# answer: dp[n][m]
⚑ Why the padding is not optional: transcribe the same recurrence onto a 0-indexed n×m table and, at 
j = 0, dp[i-1][-1] silently wraps to the previous row's last cell — already filled, often nonzero. 
LCS("aba", "ab") comes back 3 instead of 2. Java or C++ would crash on the identical code, which is at
least honest; Python just hands you a wrong answer.

5.17 Cyclic Sort, Index-as-Hash, XOR
When: array contains numbers in a known range 1..n (or 0..n) and you need missing/duplicate in O(n)
time, O(1) space.
⚑ v1's template crashed on First Missing Positive (a listed classic) because arbitrary integers send j
out of bounds. The range guard is not optional:
i = 0
whilei < len(a):
j = a[i] - 1 # a[i] belongs at index a[i]-1
if 0 <=j < len(a) anda[i] !=a[j]: # ⚑ bounds guard

else:
i +=1
# any i with a[i] != i+1 exposes missing/duplicate
Index-as-hash: mark presence by negating a[abs(x) - 1]. XOR: everything appears twice except one
→ XOR all. x & (x-1) drops the lowest set bit; x & -x isolates it; power of two ⇔ 
x > 0 and x & (x-1) == 0.

5.18 Expand Around Center ⚑
When: palindromic substrings. O(n²) time, O(1) space — beats the DP table on space and is faster to
write.
defexpand(s, l, r):
whilel >=0 andr < len(s) ands[l] ==s[r]:

best= (0, 0)

5.19 Matrix Traversal ⚑
When: spiral order, rotate image, set matrix zeroes. Not algorithmically deep, but index-fiddly enough
that people lose ten minutes.
Spiral order — shrink four boundaries:
top, bot, left, right= 0, len(m) - 1, 0, len(m[0])- 1
res= []
whiletop<=botandleft<=right:
forc in range(left, right+ 1):
res.append(m[top][c])
top+=1
forr in range(top, bot+ 1):
res.append(m[r][right])
right-=1
if top<=bot: # guard: single row left
forc in range(right, left- 1, -1):
res.append(m[bot][c])
bot-=1
if left<=right: # guard: single column left
forr in range(bot, top- 1, -1):
res.append(m[r][left])
left+=1
Rotate 90° clockwise in place: transpose, then reverse each row. Set Matrix Zeroes in O(1)
space: use row 0 and column 0 as the marker arrays; handle column 0 with a separate flag. Pitfall: the
two if guards in spiral — without them a single remaining row gets emitted twice.

Gotchas worth saying out loud:
Strings are immutable — build with a list and ''.join(parts); repeated s += c is O(n²).
// floors toward −∞: (-3) // 2 == -2. ⚑ For truncation toward zero, int(a / b) and 
math.trunc(a / b) are the same trap — both route through a float and silently lose precision past
2⁵³: int((10**18 + 1) / 3) ends in …312 instead of …333. The exact all-integer version: a // b if
(a < 0) == (b < 0) else -(-a // b).
Dict/set keys must be hashable — use tuple(lst), never a list.
Default recursion limit ≈ 1000 — deep trees/graphs need sys.setrecursionlimit or an iterative
version.
Compare node identity with is; == may be overloaded.
Python ints don't overflow — but mention 32/64-bit limits if asked to port to Java/Go/C++.

Run through before saying "done":
Empty input; single element; two elements.
All elements equal; already sorted; reverse sorted; duplicates.
Negative numbers and zero (breaks sliding-window-sum assumptions — §5.2; and all-negative trees
— §5.11).
T arget not present; k larger than n.
Linked list: empty, one node, cycle at the head.
Tree: empty, single node, fully skewed (recursion depth!).
Graph: disconnected, self-loop, no valid ordering (cycle).
Intervals: touching endpoints, one interval containing another.
Matrix: single row, single column, non-square. ⚑
Strings: single char, all same char, case sensitivity, spaces.
Values outside the assumed range (§5.17 — the guard that v1 was missing). ⚑

8. Common Mistakes
Coding before agreement — the interviewer was going to redirect you; now it costs 10 minutes.
Silent coding — narrate; the signal is the reasoning, not the keystrokes.
Improvised binary search — off-by-one death. One memorized template (§5.4), always.
Marking visited on pop instead of push in BFS — duplicate flood (§5.10).
Forgetting duplicate handling after sorting (3Sum, subsets with dups).
Claiming O(1) space while recursing — the stack counts.
Skipping the brute force — stating it is free credit and anchors the optimization story.
Not tracing the given example before declaring done — most planted bugs die here.
Mutating a structure while iterating it.
Ignoring the constraints line — it literally states the target complexity (§2.1).
⚑ Trusting a memorized template without checking its preconditions — every bug fixed
across v2 and v2.1 was a template that worked on the happy path and failed on empty input,
negative values, out-of-range values, or an unstated indexing convention.
9. Communicating Like a Senior
Lines that raise your level:
"Constraints say n up to 10⁵, so I'm aiming for O(n log n) or better."
"Brute force is O(n²) — checking every pair. The bottleneck is the inner lookup; a hashmap removes
it."
"I'll use a heap of size k rather than sorting: O(n log k) beats O(n log n) when k is small."
"Trade-off: the hashmap costs O(n) extra space to get O(1) lookups. If memory mattered, sorting
gives O(1) extra at O(n log n) time."
"Before I say done — empty input, single element, all duplicates…" (then actually trace them.)
Scale follow-ups are system-design questions in disguise: "what if the input doesn't fit in
memory?" → external sort, streaming with a heap (top-K), chunk + merge. "What if it's called by many
machines?" → shard the state.
When given a hint, take it gracefully and build on it — arguing with hints is the fastest way to fail
an otherwise good interview.
10. Final 5-Minute Cheat Sheet
Constraint → complexity: 10 → n! · 22 → 2ⁿ · 200 → n³ · 3,000 → n² · 10⁵ → n log n · 10⁶ → n · 10⁹ → log
n.
Trigger → pattern: sorted → binary search / two pointers · contiguous → window · window max →
monotonic deque · sum k with negatives → prefix + hashmap · top-k → heap · all combinations →
backtracking · count ways / min cost → DP · next greater → monotonic stack · min steps → BFS ·
dependencies → topo sort · components → union-find · weighted path → Dijkstra · 1..n missing/dup →
cyclic sort / XOR · palindrome → expand around center.
Templates to have cold: lower-bound binary search · shrinkable window · BFS with level loop ·
choose/explore/un-choose backtracking · linked-list reversal triple assignment.
Every answer ends with: time complexity, space complexity (recursion counts), edge cases traced.
Opening script: restate → constraints → example → brute force → optimize → agree → code.
